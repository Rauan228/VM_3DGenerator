# Техническое задание

## ML-модель распознавания русского жестового языка (РЖЯ) для Visual Mind

### 1. Цель

Разработать ML-модель для автоматического распознавания жестов русского жестового языка (РЖЯ) по видеопотоку с камеры.

Модель должна быть пригодна для дальнейшей интеграции в платформу Visual Mind и работать как в offline-режиме, так и через backend API.

Основная задача:

**Видео → последовательность жестов/слов РЖЯ → текст.**

В дальнейшем система должна стать основой для realtime-перевода РЖЯ в текст и взаимодействия пользователя с AI-преподавателем Visual Mind.

---

### 2. Что должно распознаваться

На первом этапе необходимо реализовать распознавание ограниченного словаря РЖЯ.

MVP:

* 50–100 наиболее употребляемых жестов/слов;
* затем расширение до 300–500;
* далее возможность масштабирования до 1000+ классов.

Примеры классов:

* привет
* пока
* спасибо
* пожалуйста
* да
* нет
* хорошо
* плохо
* человек
* дом
* школа
* университет
* учитель
* студент
* помоги
* понимать
* знать
* хотеть
* делать
* работать

Конкретный словарь будет определён отдельно на основании доступного датасета.

---

### 3. Формат входных данных

Основной input:

```text
RGB video
resolution: 640x480 / 1280x720
FPS: 25–30
duration: 1–10 sec
```

Источник:

* webcam;
* загруженный video-файл;
* в дальнейшем мобильная камера.

Модель не должна быть привязана к конкретной камере.

---

### 4. Что модель должна учитывать

Жест РЖЯ необходимо рассматривать как пространственно-временной объект.

Желательно использовать следующие признаки:

#### Руки

* координаты ключевых точек;
* положение пальцев;
* ориентация кисти;
* траектория движения;
* взаимодействие двух рук.

#### Верхняя часть тела

* положение головы;
* плечи;
* корпус;
* положение рук относительно тела.

#### Лицо

При наличии данных желательно учитывать:

* положение головы;
* брови;
* глаза;
* рот;
* выражение лица.

Это важно, поскольку в жестовых языках мимика может передавать грамматическую и смысловую информацию.

---

### 5. Архитектура

Необходимо исследовать несколько подходов и выбрать архитектуру, которая обеспечивает хороший баланс:

**accuracy / latency / размер модели / возможность realtime inference.**

Предпочтительный pipeline:

```text
Camera
   ↓
Frame sampling
   ↓
Person / hand / pose detection
   ↓
Landmarks extraction
   ↓
Temporal sequence
   ↓
Temporal model
   ↓
Gesture classification
   ↓
Text output
```

Возможный вариант:

```text
MediaPipe / YOLO / другой detector
            ↓
Hand + Pose + Face landmarks
            ↓
LSTM / GRU / TCN / Transformer
            ↓
Gesture classifier
```

Однако конкретную архитектуру не фиксируем заранее.

ML-разработчик должен провести сравнение нескольких вариантов.

---

### 6. Рассмотреть следующие модели

Минимально исследовать:

#### Вариант A — landmarks + LSTM/GRU

```text
MediaPipe
    ↓
keypoints
    ↓
LSTM / GRU
    ↓
classification
```

Плюсы:

* относительно лёгкая модель;
* подходит для realtime;
* легко запускать на CPU;
* небольшой размер модели.

---

#### Вариант B — landmarks + Transformer

```text
MediaPipe
    ↓
keypoints sequence
    ↓
Transformer Encoder
    ↓
classification
```

Проверить качество относительно LSTM/GRU.

---

#### Вариант C — видео + 3D CNN / Video Transformer

Например:

```text
Video
 ↓
3D CNN / Video Transformer
 ↓
Temporal representation
 ↓
Classifier
```

Использовать как более тяжёлый baseline.

Цель — понять, насколько дополнительная визуальная информация улучшает качество по сравнению с landmarks.

---

#### Вариант D — hybrid

При возможности исследовать:

```text
Hands + Pose + Face
        ↓
Feature fusion
        ↓
Temporal Transformer
        ↓
Classifier
```

Это потенциально наиболее интересное направление для дальнейшего развития Visual Mind.

---

### 7. Датасет

На первом этапе использовать доступные датасеты РЖЯ.

В частности необходимо исследовать:

* SLOVO;
* собственный датасет Visual Mind;
* другие открытые datasets РЖЯ, если лицензия позволяет коммерческое использование.

Для каждого датасета необходимо зафиксировать:

* количество видео;
* количество классов;
* количество уникальных исполнителей;
* длительность видео;
* разрешение;
* FPS;
* лицензия;
* распределение классов;
* наличие train/validation/test.

Особенно важно не допустить leakage между train и test.

**Видео одного и того же человека не должны случайно попадать одновременно в train и test**, если это позволяет структура датасета.

---

### 8. Предобработка

Для каждого видео необходимо получить:

```text
Frames
 ↓
Hand detection
 ↓
Pose detection
 ↓
Face landmarks
 ↓
Normalization
 ↓
Fixed-length / variable-length sequence
```

Желательно нормализовать координаты относительно тела пользователя, чтобы модель не зависела от:

* расстояния до камеры;
* положения человека в кадре;
* разрешения;
* небольших изменений масштаба.

---

### 9. Data augmentation

Необходимо предусмотреть augmentation.

Возможные варианты:

* изменение скорости видео;
* небольшое изменение масштаба;
* crop;
* translation;
* brightness/contrast;
* небольшое вращение;
* frame dropping;
* temporal jitter;
* horizontal flip — **только после проверки, допустимо ли это для конкретных жестов РЖЯ**.

Нельзя применять augmentation, который меняет смысл жеста.

---

### 10. Метрики

Основная метрика:

**Top-1 Accuracy**

Дополнительно:

* Top-3 Accuracy;
* Precision;
* Recall;
* F1-score;
* confusion matrix;
* per-class accuracy.

Для realtime:

* inference latency;
* FPS;
* RAM;
* VRAM;
* размер модели.

Особенно важна **accuracy на ранее не виденных людях**.

---

### 11. Требования к результату MVP

Для MVP целевые показатели:

```text
Количество классов: 50–100
Top-1 Accuracy: ≥ 90%
F1-score: ≥ 90%
Inference: realtime
FPS: ≥ 20–25 FPS
```

При этом accuracy необходимо считать на отдельном test set с исполнителями, которых модель не видела во время обучения.

Если 90% не достигается, необходимо предоставить:

1. baseline;
2. текущую accuracy;
3. confusion matrix;
4. наиболее проблемные классы;
5. причины ошибок;
6. предложения по улучшению датасета/архитектуры.

---

### 12. Realtime режим

В будущем модель должна работать следующим образом:

```text
Webcam
 ↓
Continuous video stream
 ↓
Sliding window
 ↓
Temporal model
 ↓
Gesture detection
 ↓
Prediction
```

Например:

```text
[0–1.2 sec] → ПРИВЕТ
[1.2–2.4 sec] → КАК
[2.4–3.8 sec] → ДЕЛА
```

Необходимо предусмотреть механизм:

* начала жеста;
* окончания жеста;
* confidence threshold;
* подавления повторных предсказаний;
* temporal smoothing.

Например модель не должна выдавать:

```text
привет
привет
привет
привет
```

если пользователь один раз показывает жест «привет».

### 17. Важный архитектурный принцип

Не делать систему исключительно как:

```text
кадр → класс
```

Это подходит только для статических жестов/алфавита.

Целевая архитектура Visual Mind:

```text
VIDEO
  ↓
SPATIAL FEATURES
(hand + pose + face)
  ↓
TEMPORAL MODEL
  ↓
SIGN RECOGNITION
  ↓
WORD / GLOSS SEQUENCE
  ↓
LANGUAGE MODEL
  ↓
NATURAL RUSSIAN TEXT
```

Таким образом ML-модель распознаёт жестовую последовательность, а отдельный NLP/LLM-слой в дальнейшем преобразует её в нормальный русский текст.

Например:

```text
Распознано:
Я → ВЧЕРА → УНИВЕРСИТЕТ → ИДТИ

↓

LLM/NLP

↓

"Вчера я ходил в университет."
```

Это разделение желательно сохранить с самого начала, чтобы ML-модель не пыталась одновременно решать задачу компьютерного зрения, распознавания жестов и генерации русского языка.
