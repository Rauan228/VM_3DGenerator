# VisualMind — видео РЖЯ → 3D-анимация аватара

Production-ready pipeline: видео человека, показывающего жест русского жестового языка,
превращается в компактные структурированные данные (`gesture.json`), которые
воспроизводятся на любом 3D-аватаре. Видео не хранятся — только движение.

## Архитектура

```
 видео (mp4, телефон, фронтально)
        │
        ▼
 ┌──────────────────────── pipeline/ ────────────────────────┐
 │ 1. extract.py    MediaPipe Holistic → pose/hands/face     │
 │ 2. normalize.py  центр плеч, плечевые единицы, ориентация │
 │ 3. smooth.py     MA (корпус) + Kalman + SavGol (кисти)    │
 │ 4. fingers.py    углы суставов, curl, нормаль ладони      │
 │ 5. gesture.py    keyframes + dedup → gesture.json (5-50×) │
 └────────────────────────────────────────────────────────────┘
        │                                   │
        ▼                                   ▼
 backend/ (FastAPI + PostgreSQL)     blender/retarget.py
   API, очередь задач, БД,             IK руки + FK пальцы →
   эмбеддинги жестов                   bake → glb / fbx / vrm
        │                                   │
        ▼                                   ▼
 frontend/ (React + Three.js + R3F)
   плеер gesture.json: скелет в 3D, скорость, пауза, перемотка,
   панель конфигурации пальцев в реальном времени
```

## Быстрый старт

```bash
# весь стек (API :8000, веб :80, PostgreSQL)
docker compose up --build

# или вручную
cd pipeline && pip install -r requirements.txt
python run_pipeline.py video.mp4 --word "привет" --report-filters

cd backend && pip install -r requirements.txt
uvicorn app.main:app --reload          # http://localhost:8000/docs

cd frontend && npm install && npm run dev   # http://localhost:5173
```

Без бэкенда плеер тоже работает: кнопка «открыть готовый gesture.json».
В `examples/` лежат два файла: `alkogol.gesture.json` — РЕАЛЬНЫЙ результат
обработки видео (detection_rate 1.0, 195 ключевых кадров), и
`privet_demo.gesture.json` — синтетическая заглушка (запястье жёстко зафиксировано,
двигается только вбок) для быстрой проверки загрузки. Для оценки точности
ретаргетинга используйте именно `alkogol.gesture.json` или свой обработанный файл.

Шум глубины монокамеры (ось z) переоценивает вынос рук вперёд — в плеере есть
два ползунка: «глубина» (по умолчанию 50%) — общее сжатие z, и «прижим»
(по умолчанию 100%) — мягкое подтягивание кистей, попадающих в силуэт торса,
к поверхности тела (контактные жесты: горло, грудь). Место исполнения жеста
по x/y при этом не меняется.

## Этапы пайплайна — ключевые решения

**Захват (этап 1).** MediaPipe Holistic, `smooth_landmarks=False` — сглаживание
делаем сами, чтобы фильтры были сравнимы и управляемы. Поза берётся из
`pose_world_landmarks` (метрические координаты, где глубина z в тех же единицах,
что x/y), а НЕ из экранных `pose_landmarks` — у последних z в условных единицах
ширины кадра и раздут в 2–3 раза, из-за чего руки «улетают» вперёд при
ретаргетинге (длина руки выходила 3–5 ширин плеч вместо анатомических ~1.3).
Видео должно быть фронтальным: при повороте корпуса боком MediaPipe теряет
глубину, ширина плеч на проекции схлопывается и нормализация ломается. Лицо прорежено с 468 до
~60 семантически важных для РЖЯ точек (брови, глаза, рот, нос): мимика и взгляд
сохраняются, объём данных падает в 8 раз. Поддержаны оба API MediaPipe —
legacy `solutions.holistic` и новый Tasks `HolisticLandmarker`.

**Нормализация (этап 2).** Опорная точка — центр плеч, масштаб — ширина плеч
(устойчива при фронтальной съёмке, не зависит от роста и дистанции до камеры).
Базис строится из плеч и бёдер и ре-ортогонализуется через SVD; origin/scale
берутся медианой по клипу, чтобы дрожание плеч не передавалось всему скелету.
Результат: жесты любых людей в единых «плечевых единицах».

**Фильтрация (этап 3).** Реализованы все три фильтра и метрики сравнения
(`compare_filters`: подавление рывка, запаздывание, сохранение пиков скорости).
Замер на данных даёт типичную картину: moving average глаже всех, но «съедает»
быстрые движения (peak_preserve ≈ 0.3); Kalman с моделью постоянной скорости
почти не теряет пики (≈ 1.0); Savitzky-Golay — компромисс. Поэтому рабочая
комбинация: MA для корпуса, Kalman + SavGol для кистей. Короткие пропуски
трекинга (< 8 кадров) интерполируются, длинные честно остаются пустыми.

**Пальцы (этап 4).** Для каждой кисти на каждом кадре: углы всех суставов,
сгиб (curl 0..1) каждого пальца, раскрытие ладони, нормаль и направление ладони,
разведение пальцев. Эти параметры хранятся отдельно от координат — именно по ним
различаются минимальные пары слов РЖЯ, и именно они идут в эмбеддинг жеста.

**gesture.json (этап 5) и сжатие.** Хранятся только ключевые кадры: сначала
выбрасываются почти статичные кадры (dedup), затем жадный отбор по ошибке
линейной интерполяции (порог 0.015 плечевых единиц ≈ 5 мм). Плеер восстанавливает
промежуточные позы Catmull-Rom-интерполяцией. Плюс квантование float до 4 знаков.
На реальных плавных жестах это даёт 5–20× по кадрам и ещё ~3× за счёт прореженного
лица и квантования — суммарно в целевом диапазоне 10–50×. Порог `tol` — ручка
«качество/размер».

## Формат gesture.json (v1.0)

```jsonc
{
  "format_version": "1.0",
  "word": "привет", "lemma": "привет", "lang": "rsl",
  "duration": 2.4, "fps": 30,
  "source_frames": 72, "stored_frames": 14, "compression_ratio": 5.1,
  "normalization": { "origin": [...], "scale": 0.21, "rotation": [[...]], "units": "shoulder_width" },
  "channels": ["pose", "left_hand", "right_hand", "face"],
  "interp": "cubic",
  "keyframes": [
    { "t": 0.0,
      "pose": [[x,y,z], ...33],
      "left_hand": [[x,y,z], ...21], "right_hand": [...],
      "face": [[x,y,z], ...~60],
      "lh_feat": { "joint_angles": {...}, "curl": {"index": 0.1, ...},
                   "palm_open": 0.9, "palm_normal": [...], "palm_direction": [...], "spread": [...] },
      "rh_feat": { ... } }
  ],
  "metadata": { "signer_id": "...", "detection_rate": 0.97, "source_fps": 30 }
}
```

Блок `normalization` позволяет восстановить абсолютный масштаб; `*_feat` —
семантическое ядро для поиска/распознавания; координаты — для воспроизведения.

## Схема БД

`gestures` — словарная единица (word, lemma, lang, category) ←1:N→
`recordings` — обработанная запись: статус (queued/processing/done/failed),
метрики качества (detection_rate, compression_ratio), пути к gesture.json и glb,
checksum, embedding. Индексы по lemma, category, (gesture_id, status).

Масштабирование на 10 000+ жестов: тяжёлые keyframes — в объектном хранилище
(S3/MinIO), в БД только пути; эмбеддинги — pgvector (`vector(240)`), поиск
похожих жестов — ANN-индекс (HNSW); очередь обработки — Celery/RQ + Redis,
воркеры без GPU (MediaPipe на CPU ≈ реальное время).

## Ретаргетинг на аватар (без внешних сервисов)

Система не зависит ни от одного облачного сервиса. Скелет аватара распознаётся
автоматически (`frontend/src/lib/boneMap.js`): резолвер приводит имена костей
любого соглашения — Mixamo, VRM/VRoid, встроенный манекен, прочие гуманоиды —
к каноническим ролям. Поэтому ретаргетер один на все форматы.

Четыре источника аватара, переключаются в плеере:

**Нейтральный человек (по умолчанию, вшит в проект).** Нейтральная
человекоподобная модель (серый манекен, риг Mixamo, полные кости пальцев) лежит в
`frontend/public/avatars/neutral.glb` и грузится сразу — ничего скачивать не
нужно. Для фотореалистичного персонажа загрузите свой .glb/.vrm.

**Встроенный манекен (офлайн, схематичный).** `frontend/src/lib/mannequin.js`
строит гуманоидный скелет с тремя фалангами на палец прямо в браузере. Лёгкий,
удобен для проверки точности жеста.

**VRM.** Любой `.vrm`-файл (например бесплатные модели с VRoid Hub) —
перетащить в плеер, грузится через `@pixiv/three-vrm`.

**GLB/GLTF.** Любой гуманоид с пальцами (риг Mixamo и совместимые).

**Метод.** Руки — двухкостевой аналитический IK: запястье ставится точно в
позицию landmark'а (якорь — плечевой сустав аватара), измеренный локоть задаёт
плоскость сгиба. Место исполнения жеста относительно тела (горло, грудь
слева/справа) в РЖЯ различает слова, поэтому позиция кисти важнее равенства
направлений сегментов — чистый aim по направлениям при иных пропорциях аватара
уводит кисть в сторону. Масштаб landmark → мир аватара — по **длине руки**,
а не по ширине плеч: «ширина плеч» у MediaPipe (центры суставов) и у ригов —
разные величины, из-за чего цели выходили за досягаемость и IK распрямлял руку
в струну. Монокулярная глубина систематически завышает вынос рук вперёд
(на реальных данных кулак, прижатый к грудине, имеет z ≈ 40 см), поэтому цель
запястья, попадающая в силуэт торса по x/y и не вытянутая к пределу
досягаемости, мягко подтягивается по z к передней плоскости груди, а глубина
локтя сжимается тем же коэффициентом — локоть прижимается к рёбрам вместе с
кистью. Надёжность измеренного pole-вектора локтя оценивается по поперечному
плечу: когда оно мало (рука прямая или локоть у оси), подмешивается
анатомический pole «локоть вниз-наружу». Пассивная рука (кисть вне кадра) не
остаётся с растопыренной rest-ладонью — пальцы мягко подгибаются к ладони.
Пальцы — aim-цепочки: каждая фаланга доворачивается мировым кватернионом до
совпадения с направлением на следующий landmark (15 костей на кисть),
иерархически от запястья к кончикам.

Запястье — особый случай: aim задаёт направление кисти, но не крутку вокруг
этой оси (куда смотрит ладонь — критично для РЖЯ: кулак «от себя» и кулак
«вверх» — разные жесты). Поэтому кисть ориентируется полностью, по двум
векторам: направление (запястье→основание среднего пальца) и нормаль ладони
(из запястья и оснований указательного/мизинца — эти точки жёстко связаны с
ладонью и не зависят от сгиба пальцев, формула работает и для кулака). Базис
ладони рига вычисляется из его собственной позы покоя, поэтому метод не зависит
от соглашения осей конкретного рига. Половина крутки переносится на предплечье
(пронация анатомически происходит там) — скиннинг не «скручивается» у запястья.

Системы координат совпадают по построению: нормализация пайплайна даёт
оси «влево/вверх/вперёд» человека, гуманоид стоит лицом в +Z с левой рукой
вдоль +X. Корректность покрыта headless-тестами:

```bash
cd frontend && npm install && npm test
```

Первый тест строит скелеты во всех соглашениях (Mixamo, RPM-стиль, VRM,
манекен) и проверяет: позицию запястий (точность IK), сторону сгиба локтей,
направления пальцев (cos > 0.99) и нормали ладоней (cos > 0.95) на всех фазах
жеста — 120/120, плюс поведенческий блок на реальных данных «Алкоголь»
(кулак у груди, локоть вниз, пассивная рука висит, пальцы расслаблены).
Второй (`tests/real_rig.test.mjs`) парсит реальный
`public/avatars/neutral.glb` и проверяет то же на его настоящей позе покоя —
ещё 27/27.

**Офлайн-экспорт glb/fbx (Blender, опционально).** `.blend` не нужен — GLB/VRM
аватара импортируется напрямую:

```bash
blender --background --python blender/retarget.py -- \
    --avatar avatar.glb --gesture привет.gesture.json \
    --out привет.glb --rig generic --fbx
```

Гибрид IK + FK: руки ведутся IK (цель — позиция запястья, что MediaPipe меряет
надёжнее всего), кисть ориентируется полностью — Damped Track на основание
среднего пальца (направление) + Locked Track на нормаль ладони (крутка, ось
кости определяется автоматически из позы покоя рига), пальцы — FK из
`joint_angles` (конфигурация кисти в РЖЯ важнее миллиметровой позиции кончика).
Маппинги костей Mixamo / generic / VRM — таблица `RIGS`, легко добавить свой.

## Веб-плеер (этап 8)

React + Three.js + React Three Fiber. Загрузка видео с прогрессом обработки,
или прямое открытие gesture.json. 3D-скелет с орбитальной камерой; цвет несёт
смысл: янтарь — левая кисть, голубой — правая (в РЖЯ роли рук различаются).
Скорость 0.25–2×, пауза, перемотка слайдером. Живая панель пальцев: столбики
сгиба каждого пальца и процент раскрытия ладони — видно, чем жест отличается
от соседнего по словарю. Интерполяция Catmull-Rom восстанавливает 30+ fps
из ключевых кадров (`src/lib/gesturePlayer.js`).

## AI-уровень (задел)

`fingers.hand_embedding_frame` даёт 15-мерный вектор конфигурации кисти;
backend при обработке строит эмбеддинг жеста: клип делится на 8 временных
сегментов, в каждом усредняются векторы обеих кистей → 240-мерный дескриптор,
инвариантный к скорости показа. Дальше по схеме из ТЗ:
видео → gesture.json → embedding → pgvector-поиск похожих → распознавание
(kNN/классификатор на дескрипторах) → генерация новых жестов (диффузия или
VAE в пространстве keyframes — формат уже к этому готов, т.к. кадры
нормализованы и дискретизованы).

## План MVP — 30 дней

Неделя 1 (дни 1–7): пайплайн на реальных видео. Снять 20–30 тестовых жестов,
прогнать extract→normalize, подобрать пороги фильтров и `tol` сжатия по
`--report-filters`, добиться detection_rate > 0.9 на телефонных видео.

Неделя 2 (дни 8–14): плеер и формат. Поднять backend + frontend (docker compose),
проверить цикл «загрузил видео — увидел скелет», зафиксировать gesture.json v1.0,
собрать первые 100 жестов словаря.

Неделя 3 (дни 15–21): аватар. ReadyPlayerMe-аватар в Blender, отладка
retarget.py на 10 контрольных жестах (включая минимальные пары, различающиеся
только пальцами), экспорт glb, воспроизведение glb в плеере рядом со скелетом.

Неделя 4 (дни 22–30): продакшн. Очередь Celery+Redis вместо BackgroundTasks,
S3 для gesture.json, pgvector + поиск похожих жестов, разметка категорий,
нагрузочное тестирование (цель: 1 видео ≈ реальное время × 1.5), деплой.

## Известные ограничения и что с ними делать

Глубина (z) с одной камеры шумная — плеер сжимает её визуально, ретаргетинг
опирается в основном на x/y; при необходимости точной глубины — вторая камера
или monocular-depth-модель поверх. Перекрытие рук телом/друг другом рвёт
трекинг — длинные пропуски не интерполируются и снижают quality_score, такие
записи стоит переснимать. Legacy Holistic не различает пересёкшиеся кисти
идеально — Tasks-API HolisticLandmarker работает лучше, он поддержан.
